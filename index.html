Flagship project

A Course In Time

Switch a hotel between Past and Present to open paths.

  • Producer / team lead, also audio, level design and programming
  • Team of 5
  • Unity 6 · C# · FMOD
  • Session 1 2026
Play in browser

What I designed

  • The era system — collision layers, object state and physics swapping in step, with a crush check so time closing around the player is a death rather than a glitch.
  • Procedural puzzle generators with Scene-view grid painting: pipe networks with a connectivity solver, and elemental puzzles that pick their own elements by counting how many valid solutions each set allows.
  • A save system built around an objective ledger, so a reloaded world remembers which doors are open and which puzzles are done.

System breakdown

Time switch

  1. Input Shift between Present and Past.
  2. Rule Collision layers, object state and physics swap in step.
  3. Outcome A crush check treats time closing around the player as a death rather than a glitch.

Puzzle generators

  1. Input Scene-view grid painting.
  2. Rule Pipe networks use a connectivity solver. Elemental puzzles count valid solutions.
  3. Outcome Puzzles that pick their own elements.

Save

  1. Input A reloaded world.
  2. Rule An objective ledger records doors and puzzles.
  3. Outcome The world remembers which doors are open and which puzzles are done.

Mechanics in the playable build

A Course In Time is a team build in development, not a shipped storefront credit.

  • Time Switch Shift between Present and Past. Platforms appear, walls vanish and hazards change.
  • Time Beam Freeze objects across both timelines; bounce beams off mirrors to hit targets around corners.
  • Box Pull Grab and move boxes into position to solve environmental puzzles.
  • Dash and Double Jump Movement abilities that open paths that were visible but previously unreachable.

Fighting game

Sword Saint: Broken Bridge

Designed by Tyler Crump

Two fighters, one 7-move set, and a storm-bridge stage in Ikemen GO.

  • Solo designer
  • Solo
  • Ikemen GO · Fighter Factory Studio (sprites and animation) · Notepad++ (editing character and stage files)

What I designed

  • Character and moveset design for two fighters, The Sword Saint and Unknown. Unknown is a mirror fighter who shares the same moveset.
  • Combat systems design: 4 normals, a two-projectile lightning special, a meter-gated super, and a back dash, plus block and a timed perfect block, and a stamina system.
  • Stage design: Broken Bridge, a 6-layer storm bridge stage with animated lightning and rain.

System breakdown

Shared moveset

  1. Input The Sword Saint and Unknown, a mirror fighter on the same moveset.
  2. Rule 4 normals, a two-projectile lightning special, a meter-gated super, a back dash, block and a timed perfect block.
  3. Outcome A stamina system sits on that set.

Broken Bridge

  1. Input One stage.
  2. Rule Six layers, with animated lightning and rain.
  3. Outcome A storm-bridge stage for the two fighters.

Tool

Tabi

A group trip planner for any trip and any group, phone-first.

  • Designer and developer (solo)
  • Solo
  • JavaScript · Express · SQLite · Leaflet
  • September 2026
Open Tabi

What I built

  • Designed and built Tabi: more than one trip on an account, each with its own invite-only group (viewer and editor roles); a day-by-day itinerary with map pins; a budget with a whole-group / per-person toggle and a budget-ceiling warning; live currency conversion; weather; a home screen that shows Today's plan during a trip and a countdown before it; Google sign-in.
  • Designed and built the earlier screens too: sign-in gate, trip overview, budget, plan, stays, flights, food, trains and people.
  • Redesigned most of the code and the visual design in later passes, for a mobile-first, phone-app feel.

System breakdown

Money states

  1. Input Each cost on the budget.
  2. Rule A cost is marked paid, committed or estimated.
  3. Outcome The three always add up to the projected cost.

Features

A group trip planner for any trip and any group. Invite-only, phone-first, and built so a different trip, group size or budget does not turn into clutter. A Japan trip was the first real use.

Also used: Visual Studio Code, GoodNotes, Aseprite.

  • Trips More than one trip on an account. Each trip has its own invite-only group, with viewer and editor roles.
  • Itinerary A day-by-day plan with map pins.
  • Budget A whole-group / per-person toggle, and a warning when spending crosses a budget ceiling. Costs stay marked paid, committed or estimated. With no budget set, the app says "No budget set".
  • Currency Live currency conversion.
  • Weather Weather for the trip.
  • Home Today's plan while a trip is on. A countdown before it starts.
  • Sign-in Google sign-in. The app is mobile-first and meant to feel like a phone app.

A decision

Never show a guess as if it were certain. Added in the 'precise money states' iteration (PR #56) and carried onto the plan (PR #59).
